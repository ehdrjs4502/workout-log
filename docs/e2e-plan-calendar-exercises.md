# 테스트 계획 — `/calendar`, `/exercises`

Playwright MCP로 두 화면을 직접 돌아본 뒤 뽑은 **테스트 항목 목록**이다.
아직 코드가 아니다. 이 목록을 검토·승인한 다음에 `.spec.ts`로 옮긴다.

- 탐색 일자: 2026-09-16 / Next 16.3.4 dev / 412×915
- 현재 커버리지: 테스트 20개가 `/`, `/session/[id]`, `/stats`, `/settings/export`를 덮는다.
  `/calendar`, `/exercises`, `/settings`는 `nav.spec.ts`의 탭 이동 수준만 있다.

## A. `/calendar`

### A-1. 기록이 없을 때 (우선순위: 상)

| # | 항목 | 확인할 것 |
|---|---|---|
| 1 | 빈 달 요약 | `이번 달` + `0회` 가 보인다. **총 볼륨 문구는 아예 없다** |
| 2 | 모든 날짜가 비활성 | 달력의 날짜 버튼이 전부 `disabled` |

> 기록이 생기면 `이번 달 2회 · 총 볼륨 3,060kg` 로 바뀐다. 두 경우의 **구조가 다르다.**

### A-3. 월 이동 (우선순위: 중)

| # | 항목 | 확인할 것 |
|---|---|---|
| 7 | 이전 달 | 제목이 `2026년 9월` → `2026년 8월` |

| 9 | `오늘` 버튼 | 8월에서 눌러 `2026년 9월` 로 복귀 |

### A-4. 이 화면의 함정 (테스트 짤 때 반드시)

- **날짜 버튼 이름이 숫자뿐이고 중복된다.** 9월 격자에 `"30"` 이 두 개(8/30, 9/30),
  `"1" "2" "3"` 도 두 개씩(9월분, 10월분) 있다.
  게다가 `name: "1"` 은 부분 일치라 `11 12 … 21 31` 까지 다 걸린다.
  → **`exact: true` + 격자 범위 좁히기가 둘 다 필요하다.** 단순히 `getByRole("button", {name:"16"})`
  로 통과하는 건 우연히 `16` 이 유일해서다.
- **`오늘` 이 두 개다.** 캘린더 헤더의 `button "오늘"` 과 하단 네비의 `link "오늘"`.
  role 이 달라 `getByRole` 로는 갈리지만 `getByText("오늘")` 은 깨진다.
- **날짜 시트에도 `닫기` 가 두 개다** (백드롭 + 헤더 X). `dialog` 로 좁혀야 한다.
  종목 추가 시트와 같은 공용 시트 컴포넌트라 같은 함정이 반복된다.
- **`1시간 0분`** — 60분을 `60분` 이라 쓰지 않는다 (7절(10)).

### A-5. 확인 필요 (버그인지 의도인지)

- 8월을 보고 있어도 요약 라벨이 계속 **`이번 달`** 이다. 숫자는 8월 것이 맞게 나오므로
  동작은 정상이고 **문구만 오해 소지가 있다.** 테스트로 굳히기 전에 의도를 정할 것.
  (`이번 달` 로 둘 거면 그대로 단언, `8월` 로 바꿀 거면 코드 수정이 먼저)

| # | 항목 | 확인할 것 |
|---|---|---|

**삭제 확인 메시지 (실측, 줄바꿈·따옴표 포함):**

```
"테스트 종목"을(를) 목록에서 지울까요?
이미 기록된 세트는 그대로 남습니다.
```

> 종목 이름이 **큰따옴표로 감싸여 있고 두 줄이다.** `toContain` 으로 단언할 때

> 그리고 메시지가 "기록된 세트는 남는다"고 말한다 = **소프트 삭제**다.
> 기록이 있는 프리셋을 지워도 과거 세션/통계가 안 깨지는지 확인하는 테스트가 있으면 좋다.
> (지금 목록엔 안 넣었다 — 시나리오가 길어서 별도 판단 필요)

### B-4. 이 화면의 함정

- **`가슴`·`등`·`하체`… 가 두 군데에 있다.** 목록의 **필터 칩**이자 추가/수정 시트의 **부위 선택 버튼**이다.
  시트가 열린 상태에서 `getByRole("button", {name:"가슴"})` 은 strict mode violation.
  → `dialog` 로 반드시 좁힐 것.
- **`{이름} 수정` 은 서로 포함 관계다.** `벤치프레스 수정` 이 `덤벨 벤치프레스 수정`,
  `인클라인 벤치프레스 수정` 까지 잡는다 → `exact: true` (7절(1), `nav.spec.ts` 에 선례 있음)
- **휴식 시간 Stepper 의 숫자 칸은 이름이 없다.** 다만 ± 버튼에는
  `기본 휴식 시간 (초) 증가/감소` 라벨이 있으니 그쪽을 쓸 것.
  (종목 추가 시트의 `이름` textbox 는 이름이 제대로 있다 — 여기만 빠진 것)
- `switch "맨몸 운동 …"` 은 role 이 `switch` 고, 접근성 이름에 **설명 문장까지 통째로** 들어간다.
  `getByRole("switch", { name: /맨몸 운동/ })` 처럼 앞머리만 잡는 편이 낫다.

## C. 빠뜨린 것 / 다음 판단

- **`/settings`** — 이번 탐색 범위 밖이었다. 가져오기(`confirm` + 파일 업로드),
  몸무게 설정, 토글들이 미검증으로 남아 있다. 별도 계획 필요.
- **시트 닫기 방법이 여러 가지** (백드롭 / X / 취소 / ESC). 전부 테스트할지,
  대표 하나만 할지 정할 것. 개인적으로는 화면당 하나면 충분하다고 본다.
- **A-5 의 `이번 달` 문구**는 테스트보다 제품 판단이 먼저다.
